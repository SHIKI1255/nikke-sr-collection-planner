# UI、VI与文案规范

本文档是页面文案、颜色、排版、图标、控件尺寸和对齐方式的统一约束。修改`src/index.html`、`src/styles/`、`src/view/`或`src/locales/`时应同步遵守；计算模型和规则集中的技术术语不受用户界面用词限制。

## 基本原则

- 可读性优先于装饰性，不通过降低字号解决布局问题。
- 颜色只作为辅助识别，必须同时保留文字或形状。
- 同一概念只使用一个用户界面术语。
- 浅色与深色共用语义变量和组件结构，只替换变量值。
- 组件尺寸来自共享变量，禁止为单个控件重复写入近似尺寸。
- 计算规则、用户界面文案和视觉语义相互独立；修改文案不得改变计算含义。

## 用户界面术语

| 概念 | 统一用词 | 不用于主要界面的用词 |
|---|---|---|
| R、SR、SSR对象 | 保养工具 | 材料、素材 |
| 输入数量 | 库存数量、个 | 材料数 |
| 10个同类工具 | 1组，可执行1次强化 | 可执行工具组 |
| 不参与规划的数量 | 保留库存 | 锁定材料 |
| 强化终点 | 目标等级 | 目标节点 |
| 概率计算结果 | 预计平均值、概率期望 | 确定消耗、必定完成 |
| 当前策略 | 当前建议使用 | 当前建议用料 |
| 策略标记 | 主用、混合/次选、不建议 | 混合或次选 |
| 实际结果 | 普通结果、大成功 | 成功、失败 |

“期望”“节点”“锚点”“凸组合”等词可以出现在计算说明中，但主要操作区域应改写为普通玩家可以直接理解的表达。

## 英文界面术语

| 中文概念 | 英文统一用词 | 避免使用 |
|---|---|---|
| 收藏品 | Collection Item | Collectible、Doll（作为正式对象名时） |
| 保养工具 | Maintenance Kit | Material、Tool Kit |
| 当前等级/目标等级 | Current Phase / Target Phase | Level、Checkpoint |
| 大成功 | Super Success | Great Success、Critical Success |
| 普通结果 | Normal Result | Failure |
| 保留库存 | Reserved Inventory | Locked Materials |
| 预计平均消耗 | Estimated Average Kit Use | Guaranteed Cost |
| 当前建议使用 | Recommended Now | Required Kit |
| 主用、混合/次选、不建议 | Primary、Mixed / Secondary、Not Recommended | Best、Bad |

英文页面使用完整自然句，不逐字翻译中文语序。`Phase`用于游戏内0–15强化阶段，`Level`只用于确实表示等级的上下文；概率结果必须使用`estimated`、`average`或`probability-based`限定。界面不得将10个工具自创为游戏术语`set`，只在说明换算关系时使用`attempt`或完整表述`one enhancement consumes 10 kits`。

## 单语言页面规则

- 中文根页面只注入`zh-CN`文案，英文`/en/`页面只注入`en`文案。
- 页面不提供语言切换按钮，不保存语言偏好，也不根据浏览器语言自动跳转。
- 两个页面共用结构、计算逻辑、规则数据、样式和本地状态；不得复制两套计算代码。
- 静态正文、动态提示、错误信息、历史记录、打印内容、无障碍标签和页面元数据必须全部来自同一语言目录。
- 英文成品不得残留中文界面文本；NIKKE、R、SR、SSR、SHIKI1255等商标、稀有度和专有名称除外。
- 中英文目录必须拥有完全一致的文案键，并通过相同计算结果、布局、打印和交互尺寸验证。
- 制作人署名固定为中文“制作：SHIKI1255”和英文“Created by SHIKI1255”，均链接至`https://github.com/SHIKI1255`。

## 文案规则

- 标题说明“用户要做什么”，避免描述内部算法。
- 按钮使用“动词＋对象”，例如“计算强化规划”“记录大成功”。
- 错误提示同时说明原因和下一步，不只显示“失败”。
- 预计值必须使用“预计”“平均”“概率期望”等限定语，不能暗示确定结果。
- 进度提示描述用户等待的结果，不显示“锚点”等内部实现。
- 数量紧跟单位；工具库存使用“个”，10个同类工具换算为“1组”。
- R、SR、SSR保持大写，中文与数字之间不额外插入空格。
- 图例、`aria-label`和悬停说明必须使用相同文本。

## 排版系统

| 变量 | 值 | 使用范围 |
|---|---:|---|
| `--font-xs` | `12px` | 表格、图例、辅助信息，页面最小字号 |
| `--font-sm` | `13px` | 标签、按钮、提示 |
| `--font-base` | `14px` | 正文、输入控件 |
| `--font-lg` | `16px` | 次级强调 |
| `--font-xl` | `18px` | 面板标题、库存数字 |
| `--font-2xl` | `20px` | 结果数字、建议工具 |
| `--font-3xl` | `24px` | 特殊大号信息 |
| `--font-display` | `29–42px` | 页面标题 |
| `--font-display-mobile` | `28–34px` | 移动端页面标题 |
| `--font-metric` | `42–56px` | 主要容量数字 |

字重只使用`400/600/700/800`四档，对应普通、中等、粗体和重度强调。`b/strong`默认映射到`--weight-bold`，核心容量和主要限制结果映射到`--weight-heavy`，不得依赖浏览器的`bolder`计算。行高只使用`1/1.25/1.5/1.6`四档。禁止重新引入9px、10px、10.5px、11px或650、750、850、900、950等零散值。

## 图标规则

- 主用、混合/次选、不建议统一使用`22×22px`图标盒。
- 三种状态图标统一使用`24×24 viewBox`和`3px`描边。
- 圆、三角、叉只改变形状与语义色，不改变尺寸、描边或对齐方式。
- 状态图标统一由 `src/view/icons.ts` 创建内联 SVG，不使用系统字体字符或另行维护的 CSS 蒙版。
- 图例、屏幕表格和打印共用同一份路径、描边与 `viewBox`，不依赖背景图形开关。
- 图标必须带相邻文字，动态表格图标必须提供`aria-label`和`title`。
- 提示符和加载动画属于反馈组件，可以改变形状，但外框尺寸仍使用`22px`。

## 控件尺寸与对齐

| 项目 | 规则 |
|---|---|
| 普通输入框、下拉菜单、按钮 | 高度`44px` |
| 主操作按钮 | 高度`50px` |
| 控件圆角 | `9px` |
| 控件水平内边距 | `12px` |
| 下拉箭头预留空间 | `40px` |
| 状态与反馈图标 | `22px` |
| 页面内容最大宽度 | `1280px` |
| 顶级板块间距 | `16px` |
| 同列板块间距 | `14px` |
| 表单与结果网格间距 | `9px` |
| 面板圆角 | `15px` |
| 面板水平内边距 | 桌面`17px`、移动端`15px` |

- “库存与目标”中的库存值、换算提示、等级、经验、目标等级和保留库存全部显式使用`text-align: left`。
- “记录本次强化”中的工具选择值与其他表单数据保持显式左对齐。
- “保留库存”输入框与普通输入框共用`44px`高度、`9px`圆角、控件内边距和焦点样式。
- 表格标题、经验值和状态图标保持居中。
- 输入控件必须设置`max-width: 100%`，所在网格子项必须设置`min-width: 0`。
- 状态网格按控件底部对齐；库存与结果卡片按网格拉伸为等高。
- 按钮文字水平和垂直居中；不得通过空格或不可见字符调整位置。
- 主按钮可以高于普通控件，但同一级别控件必须使用相同高度。
- 普通面板、状态面板和计算说明外框统一使用`--radius-panel`。
- 顶级板块、同列板块和内部网格分别使用`--space-section`、`--space-stack`和`--space-grid`，不得以相近常量替代。
- 面板标题、正文、阶段建议和计算说明的外侧内容边缘应使用共享水平内边距变量对齐。
- 同一列相邻顶级板块之间使用`--space-stack`，状态面板与普通面板不得直接相贴。

## 主题行为

- 主题模式只有`auto/light/dark`三个值。
- 首次访问默认`auto`；手动选择浅色或深色后覆盖系统设置。
- 选择自动后实时响应系统主题变化。
- 主题偏好使用独立键`nikke-sr-theme-v1`，不得与计算器库存状态混用。
- 打印固定使用浅色表面和深色文字，隐藏主题控件，并保留计算条件、概率声明、数据基线和制作信息。

## 样式源码结构

- 颜色和尺寸变量只在`tokens.css`定义；打印模式在构建时自动注入完整浅色语义配色，白纸背景单独覆盖，不手工复制一份颜色表。
- 普通组件的基础选择器只允许存在一个正式定义，不使用后置补丁层覆盖整套组件。
- `base.css`负责页面基础与顶部区域；`components.css`负责通用布局与表单；`results.css`负责结果与记录；`policy.css`负责阶段表、说明、页脚与提示。
- 普通样式模块之间不得重复基础选择器，响应式和打印覆盖仍分别集中管理。
- 响应式规则集中在`responsive.css`，只使用`1040/720/380px`三个宽度断点。
- 深色主题、交互状态、响应式、打印、高对比度和减少动画属于允许的有意覆盖。
- 构建顺序固定为`tokens → base → components → results → policy → responsive → print`。
- 最终成品必须将样式和脚本内联为单HTML；源码模板不作为发布文件。

## 可访问性与验证

- 正文和背景对比度不低于`4.5:1`。
- 大文字、控件边界和焦点状态不低于`3:1`。
- 点击目标不小于`44×44px`。
- 320px、380px、390px、720px、768px、1040px和常见桌面宽度不得出现页面级水平滚动。
- 系统高对比度模式下，下拉菜单恢复原生箭头。
- 每次修改后运行`npm test`、`npm run build`；具备依赖时再运行`npm run test:browser`。
- 文案、颜色和尺寸变量发生变化时，必须同步更新本规范及相应契约测试。
- 样式结构变化时，必须通过模块顺序、重复选择器和单文件构建契约测试。
