# 数据更新指南

## 更新原则

1. 优先核对游戏内当前说明。
2. 记录来源URL、核对日期和来源等级。
3. 不覆盖旧规则集；重大变化应新增日期版本。
4. 更新 JSON 规则集及 `config/site.json` 的选择；页面与引擎从同一数据构建，不再维护页面常量。
5. 重新核对0至15、5至15和两个历史方案。

## 必须检查

- 每次消耗数量。
- 三种工具经验值。
- 15个等级的大成功率。
- 每级经验需求和 `exp_step` 经验粒度；所有工具经验须是粒度的整数倍。
- 大成功跳转规则。
- 节点溢出经验规则。
- 个突箱子数量、概率和单次产量。

## 发布要求

数据更新PR必须说明：

- 旧值和新值。
- 来源与核对日期。
- 是否为游戏内直接确认。
- 哪些回归结果发生变化。
- 是否需要更新页面底部数据基线。

## 校验与扩展边界

构建与引擎共同使用 `src/core/rules.ts`：检查概率范围和数量、节点严格递增、经验粒度、每次消耗以及状态规模。JSON Schema 提供编辑器提示；跨字段约束以运行时校验为准。修改规则结构必须同步两者。

当前优化器只支持 R/SR/SSR 三种品质及普通强化、大成功跳转两类转移；不支持的结构应明确报错，不能静默套用。页面还要求每级可分为三个整数粒度经验行。新的优化目标应通过 `createEngine` 的优化器接口扩展，先增加独立对照测试；不要把新游戏类型直接接入现有界面。

旧状态可保留库存、等级、目标；当规则内容身份变化时，撤销历史会清空，避免以新规则回放旧记录。页脚的数据日期自动来自选中的规则集。
